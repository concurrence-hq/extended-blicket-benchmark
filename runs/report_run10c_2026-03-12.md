## 1. Overview

Run 10c applies two interventions to address problems identified in Run 10b:

1. **Revised ORDER_TESTING Dynamic Behavior** — replaces the generic "try at least 3 different orderings" guideline with a systematic permutation elimination protocol (enumerate all orderings, test one-by-one, cross off tested orderings, never repeat).

2. **Randomized label-to-role mapping** — each episode independently selects which 3 of 5 labels are correct and in what order, eliminating the alphabetical prior confound discovered in Run 10b (where 33% of Cell D's wrong-order guesses were alphabetical).

Additionally, Run 10c uses two step budgets (40 and 55) instead of Run 10b's single 60-step budget, testing whether the CG+DB architecture provides an efficiency advantage — solving the task in fewer steps — rather than an absolute capability advantage.

1. **Revised ORDER_TESTING** likely accounts for most of the improvement in Cell B. The 100% ORDER_TESTING reach rate (vs 67% in Run 10b) and systematic elimination protocol give the agent a concrete strategy rather than heuristic guessing.

2. **Deconfounded labels** likely explain why Run 10b's wrong-direction separation disappeared. With fixed labels (A→D→C), the base_llm could exploit alphabetical priors. With randomized labels, alphabetical guessing no longer works.

## 9. Conclusions

### 9.1 What We Learned

1. **The revised ORDER_TESTING DB works.** Systematic permutation elimination produces 86.7% accuracy at 40 steps for full_cg_db — up from 26.7% in Run 10b. The structured protocol converts the vague "try different orderings" into a concrete algorithmic strategy that the agent follows.

2. **Architectural separation is an efficiency effect.** At 40 steps, CG+DB wins by 33.4pp. At 55 steps, both agents converge to 86.7%. The compositional architecture doesn't unlock capabilities the base LLM lacks — it gets there faster. This is consistent with the "coordinate system revision" thesis: the CG+DB provides scaffolding that reduces wasted exploration.

3. **Deconfounding eliminates spurious base_llm advantage.** Run 10b's wrong-direction separation (base_llm > full_cg_db by 26.6pp) disappears with randomized labels. The fixed alphabetical labels in Run 10b gave the base LLM an unfair advantage via exploitable priors.

4. **100% ORDER_TESTING reach rate validates the DB trigger.** Every CG+DB episode entered ORDER_TESTING (vs 67% in Run 10b), and 93% progressed to VERIFICATION. The stagnation → order_hypothesis → ORDER_TESTING pipeline is reliable.

5. **Episode 12 (E→D→A) reveals a shared difficulty.** The maximally non-alphabetical ordering defeated all agents across all step budgets. This suggests a persistent LLM bias toward canonical orderings that even structured scaffolding cannot overcome within these step limits.

### 9.2 Limitations

- **n=15 per cell.** The Fisher p-value (0.054) approaches but does not reach conventional significance. Powering up to n=30 would resolve this.
- **Single-run.** The randomized rules provide within-run variety but don't address between-run variance.
- **3-object only.** Run 10b showed 4-object ordering is qualitatively harder. Run 10c focuses exclusively on 3-object to cleanly test the interventions.
