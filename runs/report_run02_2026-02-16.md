## 1. Run 2 Overview

### 1.1 Context

Run 2 follows directly from Run 1 (2026-02-13), which identified three root causes preventing the compositional architecture from demonstrating coordinate system revision:

1. **Environment bug:** The order-sensitive condition used an append-only `_placement_order` list. Any agent that tested objects individually before testing combinations permanently corrupted the order check, making activation impossible. This caused 0% accuracy for CG agents despite correct reasoning.

2. **Reactive-only DB triggers:** Dynamic Behaviors required a `had_unexpected_result` flag or high step counts to fire. In the order-sensitive condition, CG agents never observed any activation (due to bug #1), so there was no "unexpected result" to trigger dimension discovery.

3. **Prescriptive CG guidelines:** The Context Graph included step-by-step instructions (e.g., "Test each object A, B, C individually," "Test pairs: AB, AC, BC") rather than objective-oriented guidance. This locked agents into a fixed exploration strategy that couldn't adapt to non-standard conditions.

### 1.2 Changes Made

| Change | File | Description |
|--------|------|-------------|
| **Env bug fix** | `environment/extended_env.py` | Removals now clear objects from `_placement_order`. Order tracking is relative to current detector state, not global history. |
| **CG redesign** | `agents/context_graph.py` | Replaced prescriptive guidelines with objective-oriented ones. E.g., "Test each object A, B, C individually" became "Observe detector responses as you place and remove objects." |
| **DB stagnation trigger** | `agents/dynamic_behaviors.py` | DB1 (`exploration_stagnation`) fires proactively after 6 steps of zero activation, rather than requiring a reactive `had_unexpected_result` flag. |
| **Graded trigger evaluation** | `agents/dynamic_behaviors.py` | Trigger evaluation changed from binary YES/NO to graded 0-10 scale with per-DB thresholds. |
| **DB redefinition** | `agents/dynamic_behaviors.py` | DB1 renamed to `exploration_stagnation` (stagnation mode). DB2 `order_hypothesis` broadened with lower-then-raised threshold (5.0 -> 6.0 after smoke test). DB4 `rule_change_hypothesis` removed `requires_hypothesis_failure` gate. |
| **Activation tracking** | `agents/full_agent.py` | Added `_activation_history` and `observe_activation()` to feed activation data to DB engine. Added `_build_exploration_summary()` for trigger context. |
| **Episode runner** | `experiments/episode_runner.py` | Calls `agent.observe_activation()` after each environment step. |
| **Run 2 output paths** | `experiments/run_standard.py`, `run_extended.py` | Output to `data/traces_run2/` and `data/results_run2/` to preserve Run 1 data. |

### 1.3 What Did NOT Change

- `base_llm_agent.py` — Control agent unchanged.
- `blicket_env.py` — Base environment unchanged.
- `text_interface.py` — Text rendering unchanged.
- Experimental conditions, seeds, and episode counts identical to Run 1 (Phase 4: 3 conditions x 3 agents x 30 episodes = 270).
- LLM models: Sonnet 4.5 for actions, Haiku 4.5 for trigger evaluation.

### 3.3 What Changed and Why

**Order-sensitive: 0% -> 86-97% for CG agents.** This is entirely due to the environment bug fix. In Run 1, the append-only `_placement_order` list meant any agent that tested objects individually (as CG agents are designed to do) permanently corrupted the order check. The detector never activated, and agents concluded no objects were blickets. In Run 2, removals clear objects from the placement order, so agents can test individually, reset, and then place A-then-B to achieve activation.

**Order-sensitive base_llm: 93.3% -> 100%.** The env fix benefits all agents. In Run 1, base_llm's 2 failures were episodes where it happened to place B before A in its initial exploration. With the fix, the agent can recover from wrong-order placements by removing and re-placing in the correct order.

**Stochastic: mixed results.** base_llm dropped 6.7pp (80% -> 73.3%), cg_only improved 10pp (60% -> 70%), full_cg_db dropped slightly (80% -> 76.7%). These shifts are within the range of sampling noise for 30 episodes. The CG guideline changes (more objective-oriented) may have helped cg_only explore more flexibly. The stochastic condition remains the hardest across both runs.

**Hidden moderator: divergent.** base_llm improved (90% -> 100%), cg_only declined (83.3% -> 73.3%), full_cg_db held steady (86.7% -> 83.3%). However, the hidden_moderator results require careful interpretation due to a structural confound (see Section 5.2).

## 4. Trace Analysis: Order-Sensitive

### 4.1 Environment Fix Validated

The core fix works as designed. In Run 2, agents can test objects individually and then re-place them in the correct order:

```
Step 0: place_a  -> det=['A']     active=False  [INITIAL_EXPLORATION]
Step 1: remove_a -> det=[]        active=False  [INITIAL_EXPLORATION]
Step 2: place_b  -> det=['B']     active=False  [INITIAL_EXPLORATION]
Step 3: remove_b -> det=[]        active=False  [INITIAL_EXPLORATION]
Step 4: place_a  -> det=['A']     active=False  [COMBINATION_TESTING]
Step 5: place_b  -> det=['A','B'] active=True   [COMBINATION_TESTING]  <- ACTIVATION
```

After removing A at step 1, A is cleared from `_placement_order`. When A is re-placed at step 4 and B at step 5, the placement order is `["A", "B"]` — the correct sequence. This was impossible in Run 1.

### 4.2 The cg_only Agent: 96.7% (29/30)

The cg_only agent achieved near-perfect accuracy with the env fix alone. Its single failure (ep017) guessed `conjunctive {A, B, C}` — correct rule type and correct blickets, but over-included object C. The CG guidelines worked well: the objective-oriented phrasing ("Observe detector responses as you place and remove objects") didn't prescribe a fixed exploration sequence, allowing the agent to naturally discover that order matters through its own experimentation.

### 4.3 The full_cg_db Agent: 86.7% (26/30) — 4 Failures

All 4 failures share a common pattern: irrelevant DB triggers introduced state machine misdirection.

**Failure mode 1: Rule type misclassification (ep005, ep013)**

Both episodes fired `exploration_stagnation` (step 6) and `order_hypothesis` (step 8). The agent entered ORDER_TESTING and successfully discovered that order matters. However, after spending 10+ steps in ORDER_TESTING, the agent concluded `disjunctive {A, B}` instead of `conjunctive {A, B}`. The reasoning traces show the agent interpreted order-dependent activation as evidence that each object independently contributes (disjunctive) rather than both being required (conjunctive).

**Failure mode 2: Object over-inclusion (ep003, ep014)**

Both episodes fired `rule_change_hypothesis` as a false positive — ep003 at step 13, ep014 at step 18. This pushed the agent into MODERATOR_DETECTION, where it spent 15-21 steps investigating whether the rule had changed. During this investigation, the agent over-tested object C and ultimately included it: `conjunctive {A, B, C}`.

**CG state distribution: correct vs. wrong**

| CG State | Correct (%) | Wrong (%) | Delta |
|----------|------------|-----------|-------|
| VERIFICATION | 23.9 | 20.4 | -3.5 |
| ORDER_TESTING | 23.5 | 17.0 | -6.5 |
| INITIAL_EXPLORATION | 18.9 | 13.6 | -5.3 |
| HYPOTHESIS_EVALUATION | 13.7 | 18.4 | +4.7 |
| COMBINATION_TESTING | 12.3 | 12.2 | -0.1 |
| MODERATOR_DETECTION | 4.0 | **18.4** | **+14.4** |
| DIMENSION_DISCOVERY | 3.7 | 0.0 | -3.7 |

Wrong episodes spend 18.4% of their time in MODERATOR_DETECTION (an irrelevant state for order-sensitive), compared to just 4.0% for correct episodes. Wrong episodes also have significantly more CG transitions (14.2 avg vs 8.8) — the agent is churning through states without converging.

### 4.4 Why full_cg_db Underperforms cg_only on Order-Sensitive

The DB apparatus adds noise. The cg_only agent uses the same objective-oriented CG but has no Dynamic Behaviors to add irrelevant states. It explores systematically, discovers order sensitivity through its own experimentation, and converges efficiently. The full_cg_db agent receives the same CG guidance but is additionally bombarded with DB notifications that expand the state space with states like MODERATOR_DETECTION and RELIABILITY_TESTING — states designed for other conditions that are irrelevant here.

The DB triggers fire broadly: `order_hypothesis` fires in 93% of order-sensitive full_cg_db episodes (appropriately), but `rule_change_hypothesis` fires in 53% and `stochasticity_hypothesis` in 43% (both false positives). The CG grows from 4 states to 7-8 states, and the agent must navigate an increasingly complex state machine while making causal inferences.

## 5. Trace Analysis: Hidden Moderator

### 5.1 The Rule Switch Confound

The hidden_moderator condition starts with conjunctive rule {A, B} and switches to disjunctive {C} after 3 successful activations. The headline comparison (base_llm 100% vs full_cg_db 83.3%) obscures a critical structural dynamic: **more thorough agents trigger the rule switch more often.**

| Agent | Avg Successful Activations | Rule Switched (%) | Faced Disjunctive Rule |
|-------|---------------------------|-------------------|----------------------|
| base_llm | 2.2 | 1/30 (3%) | 1 episode |
| cg_only | 2.9 | 11/30 (37%) | 11 episodes |
| full_cg_db | 5.9 | 24/30 (80%) | 24 episodes |

base_llm answers so quickly (avg 8.9 steps) that it rarely accumulates 3 activations before submitting. It effectively solves the pre-switch conjunctive rule and exits before the hard part begins. The CG agents' structured exploration produces more activations, triggering the switch and forcing them to solve the post-switch disjunctive rule — the actual test of coordinate system revision.

### 5.2 Per-Rule-Type Success Rates

| Agent | Conjunctive (Pre-Switch) | Disjunctive (Post-Switch) |
|-------|-------------------------|--------------------------|
| base_llm | 29/29 (100%) | 1/1 (100%) — n=1, not meaningful |
| cg_only | 19/19 (100%) | 3/11 (27.3%) |
| full_cg_db | 6/6 (100%) | **19/24 (79.2%)** |

**On the post-switch disjunctive rule — the condition that actually tests coordinate system revision — full_cg_db dramatically outperforms cg_only (79.2% vs 27.3%).** This is the strongest evidence in the experiment that the Dynamic Behavior architecture adds value. The DB triggers (particularly `rule_change_hypothesis`) help the agent recognize that its established hypothesis has failed and guide it toward re-exploration under a new framework.

### 5.3 The Critical DB: rule_change_hypothesis

The `rule_change_hypothesis` DB is the most diagnostically relevant trigger for this condition. Its fire rate sharply distinguishes correct from wrong episodes among disjunctive full_cg_db episodes:

| DB | Correct (n=19) | Wrong (n=5) |
|----|---------------|-------------|
| rule_change_hypothesis | **19/19 (100%)** | **1/5 (20%)** |
| order_hypothesis | 19/19 (100%) | 4/5 (80%) |
| stochasticity_hypothesis | 17/19 (89%) | 0/5 (0%) |
| exploration_stagnation | 10/19 (53%) | 5/5 (100%) |

When `rule_change_hypothesis` fires, the agent enters MODERATOR_DETECTION and investigates the rule change — leading to 100% success. When it fails to fire (4/5 wrong episodes), the agent never receives the signal to reconsider its hypothesis. Instead, these failed episodes are routed through ORDER_TESTING (26.7% of steps) and INITIAL_EXPLORATION (27.8%) — exploring irrelevant dimensions while the actual rule change goes undetected.

**CG state time: correct vs wrong (disjunctive episodes only)**

| CG State | Correct (%) | Wrong (%) | Delta |
|----------|------------|-----------|-------|
| ORDER_TESTING | 25.3 | 26.7 | +1.4 |
| VERIFICATION | 20.0 | 12.2 | -7.8 |
| MODERATOR_DETECTION | **16.0** | **3.3** | **-12.7** |
| INITIAL_EXPLORATION | 15.3 | 27.8 | +12.5 |
| HYPOTHESIS_EVALUATION | 11.7 | 12.2 | +0.5 |
| COMBINATION_TESTING | 9.9 | 17.8 | +7.9 |

Wrong episodes spend only 3.3% of steps in MODERATOR_DETECTION vs 16.0% for correct episodes — a -12.7pp gap. They spend more time in early-stage states (INITIAL_EXPLORATION, COMBINATION_TESTING) that don't address the rule change.

### 5.4 base_llm's "Success" Is an Artifact

base_llm's 100% accuracy on hidden_moderator is not evidence of superior reasoning. It is an artifact of answering before the rule switches:

- Average 8.9 steps per episode
- Average 2.2 successful activations (below the switch threshold of 3)
- Only 1/30 episodes even encountered the post-switch rule

In the single episode where the rule did switch, base_llm happened to get the right answer — but n=1 is not a meaningful test. The base_llm never demonstrates the capability the hidden_moderator condition is designed to test: detecting and adapting to a rule change.

## 6. Trace Analysis: Stochastic

### 6.1 Results

The stochastic condition (p=0.7 activation when rule satisfied) produced the most uniform results across agents:

| Agent | Accuracy | Avg Steps |
|-------|----------|-----------|
| base_llm | 73.3% | 13.6 |
| cg_only | 70.0% | 26.6 |
| full_cg_db | 76.7% | 37.3 |

### 6.2 Failure Mode Analysis

| Agent | Wrong Objects | Wrong Rule | No Answer | Total Failures |
|-------|-------------|-----------|-----------|---------------|
| base_llm | 6 | 0 | 2 | 8 |
| cg_only | 5 | 0 | 4 | 9 |
| full_cg_db | 4 | 3+3 | 0 | 7 |

The dominant failure mode across all agents is **incorrect object identification** with correct rule type. Stochastic feedback makes it hard to distinguish "object C is irrelevant but we got unlucky" from "object C is relevant but the detector randomly didn't activate."

Notable: full_cg_db never fails to submit an answer (0 no-answer), while base_llm and cg_only both have parse failures. The DB apparatus ensures the agent keeps exploring until it has a hypothesis to submit.

full_cg_db shows a unique failure pattern: 3 episodes with both rule type and objects wrong, plus 3 with correct rule but wrong objects. The rule-type errors may reflect DB cross-talk — irrelevant triggers (order_hypothesis fires in 93% of stochastic episodes) introducing alternative hypotheses that confuse the agent about the nature of the rule.

### 6.3 The Stochastic Condition Remains the Hardest

Across both runs, stochastic is the most challenging condition. It requires statistical reasoning about probabilistic causation — recognizing that inconsistent results don't mean the rule is wrong, just that activation is noisy. No agent architecture provides a clear advantage here, though full_cg_db's slight edge (76.7% vs 70-73.3%) suggests the `stochasticity_hypothesis` DB may provide marginal benefit by directing the agent toward reliability testing.

## 7. Trace Analysis: DB Trigger Behavior

### 7.1 Overall Fire Rates

| DB | Order-Sensitive | Stochastic | Hidden Moderator |
|----|----------------|-----------|-----------------|
| exploration_stagnation | 17/30 (57%) | 19/30 (63%) | 15/30 (50%) |
| order_hypothesis | 28/30 (93%) | 28/30 (93%) | 24/30 (80%) |
| stochasticity_hypothesis | 13/30 (43%) | 19/30 (63%) | 17/30 (57%) |
| rule_change_hypothesis | 16/30 (53%) | 24/30 (80%) | 20/30 (67%) |

### 7.2 The Discrimination Problem

The DB triggers were designed to fire selectively — each for a specific causal dimension. In practice, they fire broadly across all conditions:

- `order_hypothesis` fires in 80-93% of episodes regardless of condition. It is not discriminating between "order matters" and "order doesn't matter."
- `rule_change_hypothesis` fires in 53-80% of episodes. In order-sensitive (where it's irrelevant), it fires 53% of the time.
- `stochasticity_hypothesis` fires in 43-63% of episodes. Even in order-sensitive (deterministic), it fires 43%.

The graded 0-10 evaluation at threshold 6.0 is not selective enough. Haiku tends to rate most plausible-sounding conditions at 6+, especially when the conversation shows any uncertainty or inconsistency. The triggers function more as "general exploration prompts" than as precise diagnostic tools.

### 7.3 When Discrimination Matters

Despite the broad fire rates, the triggers are not uniformly irrelevant. The critical finding from Section 5.3 demonstrates that `rule_change_hypothesis` discriminates powerfully within the hidden_moderator condition: it fires in 100% of correct disjunctive episodes but only 20% of wrong ones. The trigger's value is not in its overall selectivity but in its diagnostic precision within the right condition.

The problem is that the same trigger fires as a false positive in order-sensitive episodes (53%), where it actively harms performance by directing the agent into MODERATOR_DETECTION.

### 7.4 Implications for DB Design

The current DB design makes a tradeoff: broad triggers that never miss the target condition but generate many false positives in other conditions. A more selective approach would reduce false positives but risk missing the target. The evidence suggests that condition-specific triggers (like `rule_change_hypothesis` for hidden_moderator) provide clear value when they fire, but the false positive rate in other conditions imposes a real cost.

## 9. Summary

### 9.1 Key Findings

1. **The environment bug fix is validated.** Order-sensitive accuracy jumped from 0% to 86-97% for CG agents. The fix allows systematic exploration (test individually, then test combinations) without permanently corrupting the order check.

2. **base_llm remains the strongest overall agent (91.1%).** It outperforms compositional agents on headline accuracy. However, this partly reflects artifacts — particularly in hidden_moderator, where base_llm answers before the rule switch occurs.

3. **full_cg_db demonstrates genuine coordinate system revision on hidden_moderator.** When facing the post-switch disjunctive rule (the actual test), full_cg_db achieves 79.2% accuracy vs cg_only's 27.3%. The `rule_change_hypothesis` DB fires in 100% of correct disjunctive episodes and drives the agent to investigate rule changes. This is the clearest evidence that the compositional architecture provides capabilities the bare LLM and static CG lack.

4. **DB triggers are too broad.** All 4 DBs fire at high rates across all conditions (43-93%). The graded 0-10 evaluation at threshold 6.0 doesn't discriminate between conditions. False-positive triggers introduce irrelevant CG states that consume exploration budget and occasionally cause misclassification.

5. **full_cg_db underperforms cg_only on order-sensitive (86.7% vs 96.7%).** The DB apparatus adds noise: irrelevant triggers (particularly `rule_change_hypothesis`) push the agent into MODERATOR_DETECTION, causing object over-inclusion or rule type confusion. The static CG handles order-sensitive better because it doesn't suffer from false-positive DB notifications.

6. **Stochastic remains the hardest condition (70-77%).** No agent architecture provides a clear advantage. The dominant failure is incorrect object identification due to probabilistic feedback. This condition may require fundamentally different approaches (explicit statistical reasoning, repeated sampling) that none of the current architectures provide.

7. **The CG redesign improved cg_only.** Objective-oriented guidelines (Run 2) performed better than prescriptive guidelines (Run 1) on stochastic (60% -> 70%) and maintained performance on hidden_moderator. The less constrained exploration allows agents to discover patterns that prescriptive steps might miss.

### 9.2 Revised Understanding of Hidden Moderator

Run 1's interpretation — "hidden moderator is surprisingly easy for all agents (83-90%)" — was incorrect. The condition appeared easy because base_llm (and to a lesser extent cg_only) answered before the rule switched, effectively solving a standard conjunctive task. When agents actually encounter the post-switch rule, it is genuinely hard: cg_only achieves only 27.3%. The compositional architecture's value (full_cg_db at 79.2%) emerges precisely in this scenario.

### 9.3 Open Questions for Run 3

1. **Can DB trigger selectivity be improved?** Options include: higher thresholds (7.0+), condition-specific prompts, requiring multiple evaluation rounds, or using a more capable model for trigger evaluation.

2. **Should triggers be mutually exclusive?** If `order_hypothesis` fires, should `rule_change_hypothesis` and `stochasticity_hypothesis` be suppressed? This would reduce cross-talk but risks missing genuinely multi-dimensional conditions.

3. **What is the optimal CG state count?** Wrong episodes in order-sensitive have 14.2 avg transitions (vs 8.8 for correct). The DB apparatus may be expanding the CG past the point of usefulness. A cap on dynamic states or a state retirement mechanism could help.

4. **Should base_llm's hidden_moderator score be re-evaluated?** The 100% headline obscures the fact that base_llm almost never encounters the hard variant. A fair comparison would require either (a) forcing the rule switch at a fixed step rather than after N activations, or (b) evaluating only episodes where the switch occurred.

5. **Can the stochastic condition be improved with explicit statistical tools?** Giving agents access to a "repeat last configuration N times" macro or a Bayesian update mechanism might improve performance on probabilistic conditions.
