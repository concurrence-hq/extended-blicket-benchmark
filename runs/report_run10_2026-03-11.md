# Run 10 Report: Partial Feedback Order-Sensitive Pilot

**Date:** 2026-03-11
**Design:** 4 cells x 15 episodes = 60 total
**Seed:** 1001 | **Total cost:** $21.59
**Planning prompt:** [prompt_run10.md](prompt_run10.md)

## 1. Overview

Run 10 tests whether providing **partial feedback** — revealing the correct object identities (but not order) — breaks the information desert that produced floor effects in Run 09. Run 09 established that 3-object order-sensitive tasks are information-theoretically intractable without positive detector feedback: both agents scored near-zero across all conditions because they could never determine which objects mattered.

The partial feedback mechanism fires once per episode after the agent has explored for at least 5 steps with at least 3 unique detector configurations and zero activations. The message reveals which objects are relevant (e.g., "A, C, D") but says nothing about sequence or order.

This run crosses partial feedback with two step budgets (20 and 40) to determine whether object identification alone is sufficient, or whether agents also need enough steps to search the permutation space.

## 3. Partial Feedback Mechanism Analysis

### 3.1 Trigger Behavior

| Metric | Value |
|--------|-------|
| Episodes with PF delivered | 60/60 (100%) |
| PF delivery step | Step 5 (all 60 episodes) |
| Episodes with any detector activation | 0/60 pre-PF |

The trigger always fires at the earliest possible step (step 5). By step 5, every episode has accumulated 3+ unique detector configurations from initial exploration (e.g., {A}, {A,B}, {B}), and zero episodes have any detector activations. This confirms the information desert: in 5 steps of exploration, agents never stumble upon the correct 3-object ordered sequence.

### 3.2 Effect on Agent Behavior

The partial feedback transforms the task from a two-stage problem (identify objects + discover order) to a single-stage problem (discover order among known objects). After receiving the PF message at step 5:

- **20-step cells (A, B):** 15 remaining steps to search 6 permutations of {A, C, D}. Each permutation test requires ~3 actions (clear detector, place objects in order, observe). So agents can test roughly 5 of 6 permutations — but must also interpret the results, which costs additional steps. The budget is marginal.

- **40-step cells (C, D):** 35 remaining steps to search 6 permutations. Ample time for exhaustive search plus verification, yielding 87% accuracy.

## 7. DB and CG Analysis (Cells B and D)

### 7.1 20-Step Condition: No Meaningful Advantage

At 20 steps, the CG/DB agent performs slightly better than base_llm (13.3% vs 6.7%, +1 correct episode). However, the sample is too small for this to be statistically meaningful. The CG's ORDER_TESTING state activates after PF delivery, but with only 15 remaining steps, the systematic permutation search often runs out of time before finding the correct sequence.

### 7.2 40-Step Condition: Equal Performance

At 40 steps, both agents achieve identical accuracy (13/15 = 86.7%). The CG's systematic approach and the base_llm's less structured exploration both converge on the correct order within the step budget. This is consistent with Run 03's finding: when the object identification problem is solved (either by simple rules in Run 03 or by partial feedback here), order discovery among 3 objects is a tractable permutation search for both architectures.

### 7.3 Interpretation

Partial feedback eliminates the task feature where the CG/DB architecture could provide advantage. When the task reduces to "search 6 permutations," the problem is small enough that structured exploration provides no benefit over random search — any strategy finds the answer within 35 steps. The CG/DB advantage manifests in information-rich environments where evidence must be integrated across observations (Runs 07-08); when the search space is reduced to 6 options, brute force suffices.

## 9. Decision Criteria Assessment

### 9.1 Core Questions

**Q1: Does partial feedback break the information desert?**
Yes — completely. PF delivered at step 5 in all 60 episodes. With PF, every submitted answer correctly identified the objects (100% object accuracy vs 11% in Run 09). The task transforms from intractable to solvable.

**Q2: Does step budget matter once objects are known?**
Yes — critically. At 20 steps (15 remaining after PF), accuracy is 7-13%. At 40 steps (35 remaining), accuracy is 87%. The threshold for reliable permutation search of 3 objects is somewhere between 20 and 40 steps.

**Q3: Does partial feedback create architectural separation?**
No. At 20 steps, both agents are at floor (6.7% vs 13.3%, not significant). At 40 steps, both agents are at ceiling (86.7% vs 86.7%, identical). Partial feedback solves the object identification problem so completely that the remaining task (permutation search among 3 objects) is trivial for both architectures.

**Q4: Where does architectural separation come from?**
This run confirms by elimination that the CG/DB advantage is specific to **evidence integration in information-rich tasks** (Run 07-08: hidden moderator with rule switches). When the task is either information-starved (Run 09: no PF) or information-simplified (Run 10: PF gives objects), both agents perform identically. The CG/DB advantage exists in the middle zone where evidence is available but requires structured reasoning to interpret.

### 9.2 Comparison to Run 09 Recommended Paths

Run 09's report recommended three options:

- **Option A (this run): Partial feedback** — Confirmed: PF breaks the desert. But it breaks it so thoroughly that no architectural separation emerges. The task overshoots from "too hard for both" to "easy enough for both."

- **Option B: Increase step budget** — Run 10's 40-step cells with PF achieve 87% accuracy at only $0.52/ep average. This is dramatically more cost-efficient than Run 09's $2.19/ep for 0% accuracy. Step budget alone (without PF) would require 200+ steps per the Run 09 analysis.

- **Option C: Focus on hidden moderator** — Still the strongest recommendation for the paper. Run 10 confirms that order-sensitive tasks don't produce separation with any tested intervention.

## 10. Conclusions

### 10.1 Summary of Findings

1. **Partial feedback completely solves the object identification bottleneck.** 100% of submitted answers correctly identified {A, C, D}. The information desert from Run 09 is eliminated by step 5 in every episode.

2. **Step budget is the remaining constraint.** At 20 steps, agents know the objects but cannot reliably search 6 permutations (7-13% accuracy). At 40 steps, both agents achieve 87% accuracy. The permutation search phase requires approximately 25-35 steps for 3 objects.

3. **No architectural separation at either step budget.** Both base_llm and full_cg_db perform identically when PF provides object identity. The CG/DB architecture provides no advantage for pure permutation search — the search space (6 orderings) is small enough for brute force.

4. **6x cost reduction vs Run 09.** $21.59 for 60 episodes ($0.36/ep) vs $131.32 ($2.19/ep). Faster convergence and lower step budgets drive savings.

5. **Consistent ordering bias in base_llm.** 5 of 7 wrong answers from Cell A guessed [C, D, A], suggesting the base LLM develops systematic (but incorrect) hypotheses about permutation order.

### 10.2 CID Thesis Implications

- **Compositional architecture advantage has specific boundary conditions.** Three runs now map the landscape: (a) no evidence = no advantage (Run 09), (b) trivial evidence = no advantage (Run 10), (c) complex evidence requiring integration = clear advantage (Runs 07-08). The CG/DB architecture's value is in evidence interpretation, not search efficiency.

- **Partial feedback is a useful experimental tool but not a separation mechanism for order.** PF could be applied in future experiments where the research question is about order reasoning specifically, but for the current paper's focus on compositional architecture advantages, it confirms that order-sensitive conditions contribute a ceiling/boundary finding rather than a discrimination result.

### 10.3 Recommended Next Steps

The order-sensitive investigation (Runs 09-10) is now complete as a **boundary condition analysis**. The findings for the paper:

1. **2-object order: ceiling** (Run 03, 100% both agents) — too easy
2. **3-object order without PF: floor** (Run 09, ~0% both agents) — information desert
3. **3-object order with PF: near-ceiling** (Run 10, 87% both agents) — solved the wrong problem
4. **4-object order: floor** (Run 09, 0% both agents) — information desert squared

This confirms that order-sensitive tasks live in a binary regime for our experimental design: either trivial or intractable, with no sweet spot for architectural separation.

**For the paper:** Report the order-sensitive boundary finding in a concise section (Runs 03/09/10 as a progressive investigation), then focus the main results on hidden moderator conditions (Runs 07-08) where the CG/DB mechanism demonstrates clear, mechanistically interpretable advantages.
