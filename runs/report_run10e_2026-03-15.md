## 3. 4-Object Signal

### 3.1 Accuracy by Cell

| Comparison | Day 1 (n=10) | Day 2 (n=10) | Pooled (n=20) |
|------------|:------------:|:------------:|:-------------:|
| A (base_llm) accuracy | 1/10 (10%) | 1/10 (10%) | 2/20 (10%) |

| Difference (B − A) | +20pp | 0pp | **+10pp** |

### 3.2 Paired Episode Analysis (Pooled)

Since both agents run the same seeds, we can construct paired comparisons across all 20 seed-day combinations:

|  | A correct | A wrong |
|--|:---------:|:-------:|
| **B correct** | 1 | 3 |
| **B wrong** | 1 | 15 |

- **Concordant:** 16 (1 both correct + 15 both wrong)
- **Discordant:** 4 (3 favoring B, 1 favoring A)
- **B advantage in discordant pairs:** 3/4 = 75%

With only 4 discordant pairs, a sign test gives p = 0.625 (one-sided), far from significance. The directional signal favors B but is indistinguishable from noise.

### 3.3 Submission Rates

| Cell | Day 1 | Day 2 | Pooled |
|------|:-----:|:-----:|:------:|
| A (base_llm) | 6/10 (60%) | 4/10 (40%) | 10/20 (50%) |
| B (full_cg_db) | 8/10 (80%) | 5/10 (50%) | 13/20 (65%) |

Cell B submits more often than Cell A (+15pp pooled). This is consistent with the CG+DB architecture driving the agent toward committing to an answer rather than timing out — though the submissions are rarely correct.

### 3.4 Failure Mode Analysis

**Cell A failures (18 wrong episodes):**

| Failure Mode | Day 1 | Day 2 | Pooled |
|-------------|:-----:|:-----:|:------:|
| Timeout (no submission) | 4 | 6 | 10 (56%) |
| Wrong order (right objects) | 2 | 1 | 3 (17%) |
| Wrong rule type (guessed conjunctive) | 2 | 2 | 4 (22%) |
| Wrong objects | 1 | 1 | 1 (6%) |

**Cell B failures (16 wrong episodes):**

| Failure Mode | Day 1 | Day 2 | Pooled |
|-------------|:-----:|:-----:|:------:|
| Timeout (no submission) | 2 | 5 | 7 (44%) |
| Wrong order (right objects) | 3 | 1 | 4 (25%) |
| Wrong objects (superset or premature) | 2 | 4 | 5 (31%) |

Key observations:
- **Cell A's primary failure is timeout** (56%) — the agent runs out of steps without converging.
- **Cell B's failures are more varied** — timeouts (44%), but also object-set errors (31%) including premature submissions (e.g., ep4/Day 2 submitted after only 18 steps with 3 objects instead of 4). The CG+DB architecture appears to occasionally push the agent toward premature commitment.
- **Conjunctive misclassification** appears in Cell A (22%) but not Cell B — the architecture at least helps the agent recognize order-sensitivity as the rule type.

### 3.5 Notable Episode-Level Observations

- **Seed 1407 (F→A→C→D):** The only seed where both agents succeeded on Day 1, and the only seed where Cell A ever succeeded. Shares the same correct objects as seed 1401, which may provide partial learning signal. On Day 2, both agents failed on this seed.
- **Seed 1410 (E→C→D→F):** The only seed where Cell B succeeded on both days. This is the only replicated success in the 4-object cells.
- **Cell B ep4/Day 2 (seed 1405):** Premature submission at step 18 with only 3 objects — the full_cg_db agent submitted `[A,B,D]` when the correct answer required 4 objects `[E,A,D,B]`. This suggests a DB-driven premature convergence failure.

## 4. Synthesis

### 4.1 Combined Verdict: Stability x Signal Matrix

| Dimension | Result |
|-----------|--------|
| **3-obj stability (CAL)** | **Stable** — 10pp diff, 7/10 match rate, consistent with historical baselines |
| **4-obj stability (Cell A)** | **Stable** — 0pp diff (both at floor), 8/10 match rate |
| **4-obj stability (Cell B)** | **Marginal** — 20pp diff, 8/10 match rate (floor-inflated) |
| **4-obj separation signal** | **Weak** — +10pp pooled, inconsistent across days (+20pp D1, 0pp D2) |
| **Task tractability** | **Near floor** — Cell A at 10%, Cell B at 20%, both well below 3-obj baseline (~55%) |

**Combined assessment: Stable environment + Weak/ambiguous signal at floor.**

The instrumentation confirms the environment is stable:
- Model aliasing ruled out
- 3-object calibration replicates at 50–60% across days and is consistent with prior runs
- Sampling parameter pinning is in place

The 4-object signal is too weak and too close to the floor to justify a powered comparison:
- The +10pp pooled advantage for full_cg_db could easily be noise (p > 0.5)
- Day 1's +20pp advantage did not replicate on Day 2
- Both architectures are near-intractable at 4-object ORDER_SENSITIVE with 75 steps
- Only 1 seed (1410) produced a replicated Cell B success

### 4.2 Interpretation per Planning Prompt Framework

The result falls between two framework categories:

> **"B > A by 10–20pp pooled"** → Weak signal, could be noise. Need more data — consider n=30 powered run as exploratory.

> **"Both agents <15%"** → Task intractable at 75 steps. Consider increasing step budget or adding graded feedback before powered run.

Cell A (10%) clearly meets the intractability criterion. Cell B (20%) is marginally above but its Day 2 performance (10%) suggests the pooled 20% is inflated by Day 1 optimism.

### 4.3 Recommended Next Steps

**Do not proceed directly to a powered 4-object comparison.** The current signal is too weak, too unstable, and too close to the floor to produce meaningful results even with n=30.

**Option 1 (Recommended): Step budget pilot.**
Run a small pilot (n=5 per agent) at 100 steps to see if the floor lifts. If base_llm at 100 steps reaches 20%+ and the B–A gap persists, then a powered run becomes viable. Estimated cost: ~$35.

**Option 2: Close out 4-object ORDER_SENSITIVE.**
The 24-permutation search space may simply be too large for the current gradual feedback mechanism. Agents identify the correct objects but cannot efficiently search the ordering space in the remaining steps. Consider pivoting to a different condition (e.g., CONJUNCTIVE at 4-object, which eliminates order search) for the complexity scaling analysis.

**Option 3: Augment feedback for 4-object.**
Add a 4-object-specific hint at step 30 (e.g., confirming the first element of the correct order) to reduce the search space from 24 to 6. This changes the task but may reveal whether the architecture can exploit structured hints.

### 4.4 What Run 10e Accomplished

1. **Instrumentation gaps closed.** Temperature is pinned, API response metadata is logged, and model aliasing can be detected from this point forward.
2. **Stability confirmed.** The 3-object environment is stable at ~55% for base_llm across 4 measurement points (10c, 10d, 10e-D1, 10e-D2). The Run 10d diagnostic's 73.3% was a sampling fluctuation, not a drift event.
3. **4-object tractability limit identified.** At 75 steps, 4-object ORDER_SENSITIVE is near-intractable for both architectures. The architectural advantage, if it exists, is masked by the floor effect.
4. **Calibration seeds validated.** Seeds 2001–2010 are confirmed deterministic, varied, non-alphabetical, and correctly wired to environment activation. They are now available as a permanent stability reference.
