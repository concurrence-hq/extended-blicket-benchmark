## 2. Methodological Note

Run 3B is a **pre-specified replication batch**, not an exploratory analysis or optional stopping exercise. The methodological basis is as follows:

1. **Run 3 produced a marginal result.** The primary comparison — `full_cg_db` (93.3%, 28/30) vs. `base_llm` (76.7%, 23/30) on hidden moderator — yielded Fisher's exact p ≈ 0.08 (two-tailed), which is suggestive but does not meet conventional significance thresholds.

2. **The replication was planned before any Run 3B data existed.** The sample size (n=30 per cell), analysis plan, decision rules, and all statistical tests were specified in `artifacts/run3b_planning_prompt.md`, written and committed to the repository before any Run 3B episodes were executed.

3. **The total sample size was fixed in advance.** The combined target is n=60 per agent cell. No interim analyses were conducted during Run 3B data collection, and no stopping rules were applied other than the fixed 30-episode count per agent.

4. **Both batches are reported separately and combined.** Run 3B standalone results are presented first (Section 3) so the reader can assess the replication independently before seeing the combined analysis.

5. **This approach avoids inflated Type I error.** Unlike optional stopping (where researchers peek at accumulating data and stop when significance is reached), this design fixes the total sample size before any replication data is collected. The two-stage structure is methodologically equivalent to a single n=60 experiment that happened to be collected in two batches with different random seeds.

6. **The analysis plan includes pre-specified decision rules** (Section 5) that constrain interpretation regardless of outcome.

## 5. Primary Statistical Analysis

### Pre-Specified Test

**Comparison:** `full_cg_db` vs. `base_llm` on hidden moderator accuracy (combined n=60)

**Test:** Fisher's exact test, one-tailed (H1: full_cg_db > base_llm)

**Data:**

|  | Correct | Incorrect | Total |
|--|:-------:|:---------:|:-----:|
| full_cg_db | 54 | 6 | 60 |
| base_llm | 51 | 9 | 60 |

**Results:**

| Metric | Value |
|--------|-------|
| Fisher's exact p (one-tailed) | **0.291** |
| Cohen's h | 0.152 |
| Accuracy difference | +5.0pp |
| 95% CI for difference | [-6.8pp, +16.8pp] |

### Pre-Specified Decision Rule

The pre-specified analysis plan (Section 3 of `artifacts/run3b_planning_prompt.md`) defined three decision branches:

> - If combined Fisher's exact p < 0.05 (one-tailed) AND the replication batch shows the same direction of effect: **Claim supported.**
> - If combined Fisher's exact p < 0.05 (one-tailed) BUT the replication batch alone shows no difference or reversed direction: **Claim weakened.**
> - If combined Fisher's exact p ≥ 0.05: **Claim not supported at conventional thresholds.**

**Applying the decision rule:** Combined Fisher's exact p = 0.291 ≥ 0.05.

**Decision: Claim not supported at conventional thresholds.** The evidence does not support the claim that `full_cg_db` has a statistically significant accuracy advantage over `base_llm` on the hidden moderator condition at α = 0.05.

The effect size (Cohen's h = 0.152) is small, and the 95% confidence interval for the accuracy difference spans from -6.8pp to +16.8pp, including zero. While the point estimate favors `full_cg_db` (+5.0pp), the data are consistent with no difference or even a small base_llm advantage.

### Effect Sizes (full_cg_db vs. base_llm)

| Metric | Run 3 | Run 3B | Combined |
|--------|:-----:|:------:|:--------:|
| Accuracy difference | +16.6pp | **-6.6pp** | +5.0pp |
| Cohen's h | 0.486 | **-0.225** | 0.152 |
| Direction | full > base | **base > full** | full > base |

### Assessment

The replication batch does **not** independently support the original finding. The direction of the primary effect reversed in Run 3B (base_llm outperformed full_cg_db by 6.6pp, Cohen's h = -0.225). This is outside the range that would be expected from sampling variability around the Run 3 effect:

- Run 3 effect: h = 0.486
- Standard error of h for n=30 per group: SE ≈ √(1/30 + 1/30) ≈ 0.258
- Run 3B effect: h = -0.225
- Difference from Run 3: 0.711 (2.8 SE)

The 2.8 SE gap between the two batches is larger than expected. This suggests either: (a) the Run 3 effect was inflated by sampling variability (regression to the mean), (b) seed-dependent variability in the task is larger than expected, or (c) both. The most parsimonious interpretation is that the true full_cg_db vs. base_llm advantage on hidden moderator is small (point estimate ~5pp) and that Run 3's 16.6pp advantage was a high-side sample.

### Explaining Batch Variability: Activation-Count Decomposition (All Agents)

Every hidden moderator episode falls into exactly one of three categories based on the number of successful activations accumulated before submission. This decomposition applies to **all three agents**, not just base_llm.

**Run 3 (n=30 per agent):**

| Category | base_llm | cg_only | full_cg_db |
|----------|:---:|:---:|:---:|
| **Pre-switch** (< 3 activations) | 4/4 (100%) | 2/2 (100%) | 0 eps |
| **Exactly 3** activations | 0/7 (0%) | 0/7 (0%) | 0/2 (0%) |
| **Reasoning-eligible** (> 3 activations) | 19/19 (100%) | 21/21 (100%) | 28/28 (100%) |
| **Overall** | 23/30 (76.7%) | 23/30 (76.7%) | 28/30 (93.3%) |

**Run 3B (n=30 per agent):**

| Category | base_llm | cg_only | full_cg_db |
|----------|:---:|:---:|:---:|
| **Pre-switch** (< 3 activations) | 4/4 (100%) | 1/1 (100%) | 3/3 (100%) |
| **Exactly 3** activations | 0/2 (0%) | 0/9 (0%) | 0/4 (0%) |
| **Reasoning-eligible** (> 3 activations) | 24/24 (100%) | 20/20 (100%) | 23/23 (100%) |
| **Overall** | 28/30 (93.3%) | 21/30 (70.0%) | 26/30 (86.7%) |

**Combined (n=60 per agent):**

| Category | base_llm | cg_only | full_cg_db |
|----------|:---:|:---:|:---:|
| **Pre-switch** (< 3 activations) | 8/8 (100%) | 3/3 (100%) | 3/3 (100%) |

| **Overall** | 51/60 (85.0%) | 44/60 (73.3%) | 54/60 (90.0%) |

**Key findings:**

- **Pre-switch** episodes (activations < 3): The rule never switched. Always 100% accurate for all agents.
- **Exactly 3** activations: The agent triggers the switch on its 3rd glow but submits immediately — reporting the now-obsolete pre-switch rule. Always 0% accurate. This is a structural property of the task, not an agent-level failure.
- **Reasoning-eligible** episodes (activations > 3): The agent explores past the switch, encounters contradictory evidence, and revises its hypothesis. **100% accurate for all three agents** across both batches (combined 135/135).

The headline accuracy differences between agents are driven entirely by how many episodes land in the "exactly 3" bucket. cg_only is most vulnerable (16/60 = 26.7%), followed by base_llm (9/60 = 15.0%), then full_cg_db (6/60 = 10.0%). full_cg_db's compositional architecture drives deeper exploration, pushing more episodes past the failure zone.

**Explaining the base_llm batch-to-batch jump** (76.7% → 93.3%): Run 3 had 7 exactly-3 episodes; Run 3B had 2. This is the entire explanation — not contamination, not leakage, just sampling variability in which mode the LLM's stochastic generation selects. Fisher's exact p = 0.146 for this run-to-run difference.

**The same decomposition explains cg_only's instability** (76.7% → 70.0%): Run 3 had 7 exactly-3 episodes; Run 3B had 9. The cg_only agent's exploration pattern is more prone to landing on exactly 3 activations, producing both lower and more variable accuracy.

The hidden moderator environment is fully deterministic — the `rng_seed` parameter only affects episode identification, not environment behavior. All variation in activation counts is driven by the LLM's own stochastic generation (sampling temperature), which produces a bimodal pattern: the model either converges quickly and stops at 3 activations, or continues exploring past the gap and reaches 5+.

**Contamination was ruled out.** Searching all 60 base_llm traces for phrases like "rule change", "hidden moderator", "prior knowledge", or other meta-knowledge about the task produced zero matches. The system prompt gives no hint that rules might change. In successful post-switch episodes, the model discovers the inconsistency through observation (e.g., "Wait, this is strange! A+B was activating before but now it's NOT").

**Best estimate of true base_llm accuracy on hidden moderator:** 85.0% (51/60 pooled), 95% CI [73.4%, 93.4%].

**Correct episodes (n=54):** The dominant trajectory for correct post-switch episodes includes MODERATOR_DETECTION as a waypoint. The typical path is:
INITIAL_EXPLORATION → COMBINATION_TESTING → HYPOTHESIS_EVALUATION → MODERATOR_DETECTION → HYPOTHESIS_EVALUATION → VERIFICATION

**Incorrect episodes (n=6):** All 6 incorrect episodes followed the standard non-switching path:
INITIAL_EXPLORATION → COMBINATION_TESTING → HYPOTHESIS_EVALUATION → VERIFICATION

None of the incorrect episodes entered MODERATOR_DETECTION. The CG proceeded through its standard phases and converged on the conjunctive hypothesis without receiving the DB-triggered signal to reconsider.

### Batch Comparison

The MODERATOR_DETECTION rate dropped from 90.0% (Run 3) to 76.7% (Run 3B). This is consistent with the lower `rule_change_hypothesis` fire rate in Run 3B (76.7% vs. 93.3% in Run 3), since MODERATOR_DETECTION is triggered by this DB. The lower fire rate in Run 3B corresponds to the lower accuracy (86.7% vs. 93.3%).

## 14. Conclusion

### Summary of Findings

Run 3B was designed as a pre-specified replication batch to strengthen the Run 3 finding that `full_cg_db` outperforms `base_llm` on the hidden moderator condition. **The primary hypothesis was not supported at conventional significance thresholds.**

Applying the pre-specified decision rule: Combined Fisher's exact p = 0.291 (one-tailed), well above α = 0.05. The replication batch showed the opposite direction of effect (base_llm 93.3% > full_cg_db 86.7%). Per the analysis plan: *"Claim not supported at conventional thresholds. Report the effect size (Cohen's h) and confidence interval. Note the consistent direction across runs if applicable. Do not claim statistical significance."*

### What Was Found

While the primary claim was not supported, several findings from Run 3B are noteworthy:

1. **full_cg_db significantly outperforms cg_only (p = 0.016, BF10 ≈ 19.8).** This is the most robust pairwise finding, with a remarkably consistent effect across batches (+16.6pp in Run 3, +16.7pp in Run 3B). Adding Dynamic Behaviors to the Context Graph provides a genuine advantage over the Context Graph alone for hidden moderator detection.

2. **The omnibus test is significant (chi-squared p = 0.046).** The three agents are not equivalent on hidden moderator. This is primarily driven by `cg_only`'s lower performance (73.3% combined), which is the worst of the three agents.

3. **The mechanistic analysis remains the strongest evidence.** `rule_change_hypothesis` firing perfectly predicts success in `full_cg_db` episodes (51/51 = 100% PPV, Fisher's exact p < 0.0001). MODERATOR_DETECTION is a perfect predictor (50/50 = 100%). These results are not subject to the same batch-consistency concerns as the aggregate accuracy comparisons because they describe a deterministic mechanism: when the DB fires, the agent enters MODERATOR_DETECTION, re-examines its hypothesis, and arrives at the correct answer. Every single time.

4. **The failure mode is uniform.** Across all 120 combined agent-episodes that were incorrect (15 base_llm errors, 16 cg_only errors, 6 full_cg_db errors across all runs), every single one guessed the pre-switch conjunctive {A,B} rule. No agent ever detected the switch but identified the wrong post-switch rule.

### Interpretation

The revised picture of hidden moderator performance is:

- **`full_cg_db`** achieves the highest combined accuracy (90.0%) through a specific mechanism: the `rule_change_hypothesis` DB detects anomalous activation patterns after the rule switch, triggers MODERATOR_DETECTION, and enables hypothesis revision. When this mechanism fires, it is infallible (51/51). When it does not fire, the agent falls back to the same failure mode as other agents.

- **`base_llm`** achieves surprisingly high combined accuracy (85.0%), driven largely by Run 3B's 93.3% result. This suggests that Claude Sonnet 4.5 has substantial native ability to detect and adapt to rule changes through in-context reasoning alone, without architectural scaffolding. The Run 3 result (76.7%) may have underestimated this capability.

- **`cg_only`** performs worst (73.3%), suggesting that the Context Graph's structured exploration — without the DB-triggered hypothesis revision — may actually *interfere* with hidden moderator detection. The CG's phase-based progression may lead to premature convergence on the initial hypothesis, and without the rule_change_hypothesis DB to interrupt this trajectory, the agent lacks the mechanism to reconsider.

### Revised Claims

The evidence supports the following claims:

- **Supported:** Dynamic Behaviors provide a measurable advantage over the Context Graph alone for hidden moderator detection (+16.7pp, p = 0.016, consistent across batches).
- **Supported:** `rule_change_hypothesis` is a mechanistically transparent, near-perfect predictor of success on hidden moderator (100% PPV, 94.4% sensitivity, Fisher's p < 0.0001).
- **Not supported:** The full compositional architecture (CG+DB) has a statistically significant accuracy advantage over the bare LLM on hidden moderator (p = 0.291, BF10 = 1.58).
- **Emerging concern:** The Context Graph without Dynamic Behaviors may harm hidden moderator performance relative to the bare LLM (73.3% vs. 85.0%, though p = 0.177 does not reach significance).

### Implications for the Compositional Intelligence Thesis

The Run 3B results challenge the simple narrative that "more compositional scaffolding = better performance." Instead, they reveal a more nuanced picture:

1. The **Dynamic Behaviors component** (specifically `rule_change_hypothesis`) provides genuine, mechanistically transparent value for coordinate system revision. This is the strongest evidence in the dataset.

2. The **Context Graph component** provides structure that can be either helpful (when paired with DBs that interrupt maladaptive trajectories) or harmful (when its structured progression leads to premature convergence without a mechanism for interruption).

3. The **bare LLM** is more capable than Run 3 suggested. Claude Sonnet 4.5's in-context reasoning appears sufficient to detect hidden rule changes in many cases, though less reliably than the DB-mediated mechanism (no Run 3B batch showed the perfect 100% predictive value that rule_change_hypothesis achieves).

The story is not "compositional architecture beats the bare LLM" but rather "specific compositional components (Dynamic Behaviors) provide a reliable detection mechanism that the bare LLM achieves through less transparent means." The value proposition shifts from aggregate accuracy improvement to mechanistic reliability and interpretability.
