# Run 10d Report: Powered Replication + Attribution + 4-Object Pilot

**Date:** 2026-03-13
**Design:** 5 cells, 160 episodes (Phase 1: 3×50, Phase 2: 2×5)
**Seed:** Phase 1: 1201–1250 | Phase 2: 1301–1305 | **Total cost:** $107.93
**Planning prompt:** [prompt_run10d.md](prompt_run10d.md)

## 1. Overview

Run 10d is a powered replication of Run 10c's 3-object efficiency advantage with two additions: (1) a `cg_only` attribution arm to decompose the architectural contribution into Context Graph structure vs. Dynamic Behavior content, and (2) a small 4-object pilot to test scalability.

### 1.1 Motivation

Run 10c (n=15) found full_cg_db (86.7%) outperformed base_llm (53.3%) by 33.4pp at 40 steps (Fisher p = 0.054). However, the sample was underpowered and lacked an attribution arm. Run 10d addresses both: n=50 per cell provides ~97% power at the observed effect size, and the new cg_only cell decomposes the contribution.

The cg_only arm (Cell B) performed *worse* than both endpoints at 42.0%, with the lowest submission rate (68%). The Context Graph structure alone, without Dynamic Behaviors, appears to impair rather than aid performance on this task.

## 3. Trace-Level Mechanistic Analysis (Phase 1)

Despite the null accuracy result, the trace data reveals the architecture is working as designed at the behavioral level — the treatment simply doesn't translate into outcome improvement.

### 3.1 Explicit Enumeration

| Cell | Agent | Explicit Enumeration | Rate |
|------|-------|:--------------------:|:----:|
| A | base_llm | 7/50 | 14.0% |
| B | cg_only | 14/50 | 28.0% |
| C | full_cg_db | 47/50 | **94.0%** |

The DB's `order_hypothesis` behavior, which injects the systematic permutation elimination protocol, drives near-universal explicit enumeration reasoning in Cell C. The base_llm occasionally enumerates on its own (14%), and the CG structure doubles this rate (28%), but the DB content is the primary driver. This confirms the architecture changes agent reasoning — it just doesn't change outcomes.

### 3.2 Distinct Orderings Tested

Distribution of distinct correct-object orderings tested per episode:

| Orderings Tested | Cell A (base_llm) | Cell B (cg_only) | Cell C (full_cg_db) |
|:----------------:|:-----------------:|:----------------:|:-------------------:|
| 2 | 8 | 4 | 2 |
| 3 | 15 | 17 | 22 |
| 4 | 18 | 26 | 15 |
| 5 | 9 | 2 | 10 |
| 6 | 0 | 1 | 1 |

All three cells have similar coverage distributions. The modal bin is 4 orderings for Cell A, 4 for Cell B, and 3 for Cell C. Despite the higher enumeration rate, Cell C does not achieve meaningfully higher coverage — the bottleneck is the 40-step budget, not the reasoning strategy. The agent "knows" it should test all 6 but runs out of time after ~3–4.

### 3.3 CG State Trajectories

**Cell B (cg_only):** Active CG with avg 2.8 successful transitions per episode.

| Final State | Count |
|-------------|:-----:|
| VERIFICATION | 35 |
| HYPOTHESIS_EVALUATION | 12 |
| COMBINATION_TESTING | 3 |

| State Ever Visited | Count |
|--------------------|:-----:|
| COMBINATION_TESTING | 50/50 |
| HYPOTHESIS_EVALUATION | 49/50 |
| VERIFICATION | 36/50 |

The CG is actively guiding Cell B through structured phases. All 50 episodes transition through COMBINATION_TESTING; most reach HYPOTHESIS_EVALUATION; 36 reach VERIFICATION. The problem is that without ORDER_TESTING (which is only added by the DB), the CG channels the agent through phases that don't address the order-sensitive task structure.

**Cell C (full_cg_db):** CG enriched with DB-added states.

| CG State | Visits |
|----------|:------:|
| COMBINATION_TESTING | 66 |
| ORDER_TESTING | 52 |
| VERIFICATION | 34 |
| DIMENSION_DISCOVERY | 27 |
| HYPOTHESIS_EVALUATION | 18 |
| MODERATOR_DETECTION | 5 |

Cell C's CG is expanded at runtime by DB fires: ORDER_TESTING appears in 52 state transitions, DIMENSION_DISCOVERY in 27, and MODERATOR_DETECTION in 5. These states are absent from Cell B's trajectory entirely.

### 3.4 Dynamic Behavior Activation (Cell C)

| Behavior | Episodes Fired | Fire Rate |
|----------|:--------------:|:---------:|
| order_hypothesis | 50/50 | 100% |
| exploration_stagnation | 45/50 | 90% |
| rule_change_hypothesis | 15/50 | 30% |

The `order_hypothesis` DB fires in every single episode, injecting the ORDER_TESTING state and systematic permutation protocol. The `exploration_stagnation` DB fires in 90% of episodes, adding DIMENSION_DISCOVERY. The `rule_change_hypothesis` fires in 30%, adding MODERATOR_DETECTION — this is the behavior identified in Run 10c Episode 6 as potentially diverting agents from the correct search.

### 3.5 ORDER_TESTING Entry and Correlation with Success

| | Entered OT | Did Not Enter OT |
|--|:----------:|:----------------:|
| **Success** | 20 | 8 |
| **Failure** | 17 | 5 |
| **Total** | 37 (74%) | 13 (26%) |

ORDER_TESTING was entered in 37/50 episodes (74%), with an average entry at step 14.4. Success rate conditional on OT entry is 54.1% (20/37), compared to 61.5% (8/13) without OT entry. Entering ORDER_TESTING does not predict success — if anything, episodes that skip it do slightly better.

**Failure modes within ORDER_TESTING (17 episodes):**

The dominant failure mode within ORDER_TESTING is timeout (7/17 = 41%), consistent with the coverage analysis: the agent enters OT at step ~14 with ~26 steps remaining, but needs ~7 steps per ordering test, limiting coverage to ~3–4 of 6 orderings.

## 6. Interpretation and Decision

### 6.1 Decision Tree Outcome

Per the planning prompt decision tree:

```
Cell C vs Cell A?
├── C > A by ≥15pp, p < 0.01 → [not reached]
├── C > A by 10–15pp, p < 0.05 → [not reached]
├── C > A by <10pp or p > 0.05 → ✓ THIS BRANCH
│   → Failed replication
│   → Investigate: did randomization of new seeds change difficulty?
└── A > C (wrong direction) → [not reached]
```

**Verdict: Failed replication.** The C–A gap is exactly 0pp (p = 1.0).

### 6.2 What the Architecture Does (and Doesn't Do)

The trace data tells a clear but surprising story:

1. **The architecture works at the behavioral level.** The DB fires in 100% of episodes, adds ORDER_TESTING to the CG in 74%, and induces explicit enumeration reasoning in 94%. This is exactly what was designed.

2. **The architecture does not improve outcomes.** Despite radically different reasoning strategies (94% vs 14% explicit enumeration), Cell C and Cell A achieve identical accuracy, identical submission rates, and identical order-correct counts.

3. **The bottleneck is execution, not strategy.** All cells test approximately the same number of orderings (modal 3–4 of 6) despite different reasoning quality. The 40-step budget constrains execution regardless of how well the agent plans. The agent "knows" it should test all 6 orderings but cannot execute quickly enough.

4. **The CG structure alone is harmful.** Cell B (cg_only) underperforms Cell A (base_llm) by 14pp (42% vs 56%, p = 0.23). The CG's phase transitions channel the agent through INITIAL_EXPLORATION → COMBINATION_TESTING → HYPOTHESIS_EVALUATION → VERIFICATION, which does not address the order-sensitive structure. Without the DB adding ORDER_TESTING, the CG wastes steps on irrelevant phases.

5. **The DB recovers the CG's cost.** Cell C (56%) matches Cell A (56%) but outperforms Cell B (42%) by 14pp. The DB's ORDER_TESTING protocol compensates for the CG's overhead, achieving parity with the unscaffolded agent but not exceeding it.

### 6.3 Why Run 10c Showed a Large Effect

The Run 10c result (86.7% vs 53.3%, +33.4pp) was likely a small-sample artifact:

- **base_llm was stable:** 53.3% (10c, n=15) → 56.0% (10d, n=50). The baseline is consistent.
- **full_cg_db regressed:** 86.7% (10c, n=15) → 56.0% (10d, n=50). The treatment effect vanished.
- **Favorable seed draws:** At n=15, Run 10c's seeds may have been disproportionately favorable for the systematic protocol. Run 10d's 50 seeds include the harder tail of the distribution.
- **Submission rate convergence:** Run 10c showed a 33pp submission gap (100% vs 67%). Run 10d shows both at 82%, suggesting the prior gap was also a small-sample artifact.

### 6.4 Implications for the Research Program

The null result has important implications for the Gopnik compositional intelligence paper:

1. **ORDER_SENSITIVE is not a discriminating condition at this complexity level.** At 3-object ordering (6 permutations, 40 steps), the base LLM can brute-force the search space well enough that architectural scaffolding provides no advantage.

2. **The architecture changes process without changing outcomes.** This is a genuine finding — it means the compositional advantage may be task-complexity dependent. The architecture may only separate from baseline when the search space exceeds the LLM's native exploration capacity.

3. **The efficiency claim needs revision.** Run 10c's "solves it in fewer steps" narrative does not hold at n=50. The paper should report both 10c (suggestive, n=15) and 10d (null, n=50) results.

4. **CONJUNCTIVE/DISJUNCTIVE may still show separation.** The Run 08 results (conjunctive/disjunctive conditions, n=50) showed statistically significant CG+DB advantages on harder conditions. The ORDER_SENSITIVE null does not invalidate those findings.
